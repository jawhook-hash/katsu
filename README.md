# 活（Katsu）

iPhone 用の 30分活動記録 PWA。スタートで開始時刻を記録 → 30分後に iPhone のショートカットで知らせる →
活動内容（分類＋自由記述）を入れて保存。カレンダーと統計で振り返る。タイマーなしの手入力もできる。

## 構成
- 公開先: https://jawhook-hash.github.io/katsu/ （リポジトリ jawhook-hash/katsu・public、Pages は main の /docs。push は毎回確認）
- `docs/` … 公開するアプリ本体
  - `index.html` / `style.css` / `app.js` … 画面と動き
  - `sw.js` … アプリ本体だけをキャッシュ。**部品を変えたら `CACHE` の番号を上げる**
  - `manifest.json`・`icon-*.png`
- `make_icons.py` … アイコン生成（`python C:/Users/asada/ClaudeWk/Katsu/make_icons.py`）
- PC での確認: プレビュー設定 `katsu`（`python -m http.server 8778 --directory Katsu/docs`）

## 30分後の知らせ方（ショートカット）
アプリは**音を出さない**（活動中に音声を流す使い方があるため。最初の試作は「30分の無音＋アラーム」を
流し続ける方式だったが、ユーザーの指示でやめた）。ホーム画面アプリは画面ロック中に止まり、
サーバーなしでは通知も予約できないので、スタートで iPhone の「ショートカット」を呼ぶ
（`shortcuts://run-shortcut?name=活タイマー`。名前は設定で変えられる。空欄なら呼ばない）。

ショートカット App で「活タイマー」を1つ作る（アクション名は iOS の版で少し違うことがある）。
新しい iOS では最初の画面が「ライブラリ」で「＋」が見つけにくい。ホーム画面の「ショートカット」アイコンを長押し →
「新規ショートカット」で作る画面が開く。
- **時計のタイマー型（使用中）**
  1. 「タイマーを開始」… 30 分
  - マナーモードでも鳴る。止めるまで鳴り続ける
- **リマインダー型（この iPhone では動かなかった）**
  1. 「日付」（現在の日付） 2. 「日付を調整」… 30 分を追加
  3. 「新規リマインダーを追加」… 通知の欄に「調整済みの日付」
  - 正しく組んでも実行時に「指定された通知時刻は無効です」が出た（2026-10-25）。
    「日付を書式設定」で文字にしてから渡す回避策は未確認

ショートカットが動いたあとは、自分で「活」に戻る。活で「中止」しても、作られたリマインダー／タイマーは消えない。

## 仕様
- タイマー: 状態は開始時刻（localStorage `katsu.session`）から計算。開き直して 30分過ぎていれば入力画面
- 記録: IndexedDB `katsu` → `records`（`{id, start, end, min, cat, text}`。id は開始時刻ミリ秒、重なれば +1）
- 手入力: タイマー画面「＋記録を追加」、カレンダーの日付一覧「＋この日に記録を追加」。日付・開始・長さ（分）・分類・内容。
  記録をタップすると同じ画面で編集・削除
- 分類: 初期値 学習・読書・運動・仕事・その他。作った順に色の枠（8色）を割り当て、色は分類について回る。
  記録のある分類は削除できない（名前の変更は可）
- カレンダー: 月表示・日ごとの回数を濃淡で。日付をタップでその日の一覧
- 統計: 週（月曜はじまり）・月・年・全期間。合計時間・回数・活動日・活動日の平均、推移の棒、分類別、
  開始時刻の時間帯、連続日数（今日まだでも昨日まで続いていれば「現在」に数える）
- 控え: 設定の「書き出す」（共有シート → ファイルに保存）・「読み込む」（同じ id は飛ばす）
- **Safari のタブとホーム画面の「活」は保存場所が別。ホーム画面から消すと記録も消える**
- 試験モード: `?test=10` で 10秒。ショートカットは呼ばず、記録は別の保存場所（`katsu-test`）
